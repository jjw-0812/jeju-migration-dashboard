# 제주 인구이동 대시보드

정적 HTML과 Google Apps Script로 제주와 다른 시도 간 전입·전출·순이동을 표시합니다.

## 조회 기능

- 월별 현황, 연간·전년도 비교, 시작연월~종료연월 기간 선택
- 전체 연령, 만 20~39세, 10대~90대(각 10년 구간), 남성·여성·전체
- 연간 월별 표와 순이동 차트, 시도별 누계, 전년 동기간 증감
- 지역별 결과와 월별 비교 CSV 내보내기

연령은 만 나이입니다. 90대는 90~99세이며, 전체 연령에는 0~9세와 100세 이상도 포함됩니다. 연령·성별을 바꿀 때는 이미 받은 자료로 다시 계산하므로 추가 API 호출이 없습니다.

완료된 해는 1~12월을, 진행 중인 해는 지난달까지를 집계합니다. 예를 들어 2026년 11월 조회 시 2026년 1~10월과 2025년 1~10월 누계를 비교하며, 월별 표에는 전년도 11~12월도 참고로 표시합니다. 지난달까지 조회 가능하다는 것이 실제 통계 공표를 보장하지는 않습니다. 미공표·자료 없음·조회 오류·연령 필드 누락은 `—`로 표시하고 0명으로 합산하지 않습니다. 필수 월 하나라도 누락되면 해당 누계와 비교값을 비웁니다. 지원 시작연도는 2024년이므로 2024년 조회 시 2023년 비교값은 없습니다.

기간 선택에서는 시작월과 종료월을 모두 포함합니다. 연도를 넘는 기간과 12개월을 넘는 기간도 조회할 수 있습니다. 예를 들어 2025년 7월~2026년 6월은 2024년 7월~2025년 6월과 비교합니다. 전년 비교월이 2024년 1월 이전이면 해당 월은 요청하지 않고 비교 누계는 비웁니다. 역전된 기간과 지난달 이후 기간은 조회할 수 없습니다. 시작·종료연월은 조회 기간 메뉴에서 **기간 선택 · 전년도 비교**를 선택하면 표시됩니다. 이 기능은 기존 월별 API를 재사용하므로 Apps Script를 다시 교체할 필요가 없습니다.

월별 화면에서는 당시 행정구역을 유지합니다. 연간 비교에서는 2026년 7월 이전 광주(29)·전남(46)을 합산해 이후 전남광주통합특별시(12)와 같은 지역 범위로 비교합니다. 코드 12와 2026년 9월 양방향 조회는 이 프로젝트에서 실제 API로 확인했습니다. 변경 시점은 2026년 7월로 적용합니다.

## 적용 순서

1. [apps-script/Code.gs](apps-script/Code.gs)의 **전체 내용**으로 Apps Script의 기존 `Code.gs`를 교체하고 저장합니다. 기존 스크립트 속성 `DATA_GO_KR_SERVICE_KEY`는 그대로 사용하며 키를 HTML에 넣지 않습니다. 이전에 저장한 `JEJU_MERGED_REGION`도 유지합니다. 없다면 이미 확인된 코드 12를 사용하므로 코드 탐색을 다시 실행할 필요가 없습니다.
2. 편집기에서 `testApi`를 실행하고 연령대별 `inboundAgeBands`/`outboundAgeBands`를 확인합니다. 각 배열은 `[남성, 여성]`입니다. 누락 필드는 `null`입니다.
3. **배포 → 배포 관리 → 대시보드에 연결된 배포의 수정 → 새 버전 → 배포**를 선택합니다. 기존 웹 앱 URL을 유지합니다.
4. 기존 `/exec?action=health`에서 `version: "jeju-age-bands-20261105-v6"`, `features: ["ageBands"]`를 확인합니다.
5. `index.html`과 `migration.js`를 함께 GitHub Pages 소스에 반영합니다. 두 파일 모두 필요합니다. `migration.js`를 수정하면 `index.html`의 스크립트 URL에 붙인 `v` 값도 파일의 SHA-256 앞 12자리로 갱신합니다. 브라우저가 이전 계산 코드를 재사용하지 않도록 하기 위한 버전입니다. 웹 앱 주소를 바꾼 경우 `index.html`의 `DEFAULT_ENDPOINT`도 변경해야 합니다. 예전에 브라우저에 저장된 연결 주소는 사용하지 않고 현재 배포의 기본 주소를 사용합니다.
6. 대시보드에서 2026년 9월/전체 연령/전체 성별을 조회합니다. 기존 검증 기준은 15개 지역, 전입 1,878명·전출 2,099명·순이동 -221명입니다. 이후 10대/90대와 연간 조회를 확인합니다.

Apps Script 편집기 조작과 웹 앱 배포는 별도 권한이 필요하며, 저장소를 푸시하는 것만으로 Apps Script가 업데이트되지는 않습니다. 기존 v5 서버는 전체 연령·청년층은 반환하지만 새 `ageBands`가 없어 10대~90대 값이 비워집니다. 서버를 먼저 업데이트한 후 프런트엔드를 배포하세요.

## 요청과 성능

대시보드는 Apps Script에 월마다 `month=YYYYMM&callback=jejuCb_…`를 요청합니다. 서버는 공공데이터 API에 각 지역 쌍의 `mvinAdmmCd`, `mvtAdmmCd`, `srchFrYm`, `srchToYm`, `lv=1`, `type=json`, `numOfRows=10`, `pageNo=1`, `serviceKey`를 보냅니다. 날짜 범위는 한 달이며 연령 필드는 응답에서 합산합니다.

기간 조회는 선택 기간과 전년도 같은 기간의 월별 요청을 순차 수행합니다. 기간이 길수록 최초 조회 시간이 길어집니다. 연간 조회를 처음 할 때는 최대 24개월, 공공데이터 API 기준 최대 768건이 필요합니다(지역 통합 이후 월은 30건, 이전은 32건). 서버는 완전한 월 결과를 6시간, 부분 자료를 10분 캐시하고, 브라우저는 정상 월 결과를 5분 재사용합니다. 서버 캐시는 보존이 보장되지 않습니다. 최초 연간 조회에는 시간이 걸릴 수 있으며 진행 상황과 중단 버튼을 제공합니다. 실패한 월은 자동 반복하지 않고, 다시 조회하면 정상 월 캐시는 재사용하고 실패한 월을 재조회합니다.

## 로컬 실행과 검증

별도 설치·빌드가 필요하지 않습니다. 기존 격리 체크아웃을 사용하며 별도 Git worktree를 만들 필요가 없습니다.

```sh
cd /workspace/jeju-migration-dashboard
python3 -m http.server 8000 --bind 127.0.0.1
```

별도 터미널에서:

```sh
cd /workspace/jeju-migration-dashboard
node tests/calculations.test.cjs
node tests/browser.cjs
```

계산 테스트는 Node 기본 기능만 사용합니다. 기간 선택·연도 경계·역전 기간 차단·CSV 범위도 검사합니다. 브라우저 테스트는 실행 환경에 제공된 Playwright와 `/usr/bin/chromium`을 사용하며 로컬 서버가 필요합니다. 테스트는 실제 통계와 구별되는 모의 응답으로 연령대 경계·성별·누락 월·통합 전후 합산·캐시·취소·CSV·모바일 표시를 확인합니다. Apps Script의 실제 v6 응답은 원격 배포 후 별도로 검증해야 합니다.
